## 2. Покрытие кода и ветвей

Покрытие измерено командами:

```powershell
python -m coverage run --branch --source=src -m pytest -q
python -m coverage report --show-missing
```

До начала работы набор из 27 тестов давал 99 %: в `processing_module.py`
не проверялась одна ветвь (строка 10). После добавления тестов качества
и исправления дефектов все 165 операторов и 46 ветвей покрыты. Целевой
порог варианта (70 %) превышен на 30 процентных пунктов, внутренняя цель
(90 %) — на 10.

Важно понимать, что 100 % покрытия не означало отсутствие ошибок: оба
дефекта находились в уже покрытом коде. Их выявило именно эквивалентное
разбиение (класс «неконечные числа» и класс «повторный запрос после сбоя»),
а не рост покрытия.

## 3. Плотность дефектов

Число непустых строк я посчитал командой:

```powershell
(Get-ChildItem src\*.py | Get-Content | Where-Object { $_.Trim() -ne "" }).Count
```

Плотность = 2 дефекта / 180 строк × 1000 ≈ 11,1 дефекта на 1000 строк.
Для небольшого учебного проекта это ожидаемое значение: оба дефекта —
контрактные, находятся на границах модулей (чтение XML и конвейер).
