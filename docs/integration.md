# Интеграция модулей

## Выбранная стратегия

Для проекта выбрана функционально-ориентированная интеграция, заданная для
варианта 4. Сначала проверяется полный пользовательский сценарий, затем его
части. Это удобно для небольшой консольной программы с чёткой цепочкой действий.

## Схема потока данных

```text
Ввод и валидация
        |
        v
    input.xml
        |
        v
Обмен строк с минимумом и максимум
        |
        v
  processed.xml
        |
        v
Форматирование и вывод
        |
        v
    result.xml
```

## Формат XML

```xml
<?xml version='1.0' encoding='utf-8'?>
<matrix-message version="1.0" stage="input" rows="2" columns="2">
  <row number="1"><value>1.0</value><value>2.0</value></row>
  <row number="2"><value>3.0</value><value>4.0</value></row>
</matrix-message>
```

## Сопоставление данных

| Объект Python | Поле XML | Преобразование |
|---|---|---|
| число строк | `rows` | `int` -> строка атрибута |
| число столбцов | `columns` | `int` -> строка атрибута |
| номер строки | `row/@number` | нумерация с 1 |
| элемент матрицы | `row/value` | `float` <-> текст |
| этап обработки | `stage` | строка |
| версия схемы | `version` | строка `1.0` |

## Обработка ошибок

- отсутствие модуля приводит к `ModuleUnavailableError`;
- пустая, непрямоугольная или нечисловая матрица приводит к `InvalidDataError`;
- отсутствие XML-файла после ожидания приводит к `IntegrationTimeoutError`;
- неподдерживаемая версия XML-схемы приводит к `VersionConflictError`.
