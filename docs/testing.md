# План и протокол тестирования

Документ подготовил Боцман Алексей Андреевич (Т9-ИП-25-2) в рамках
лабораторной работы №4 «Тестирование и обеспечение качества ПО».

## 1. Объект и цели

Объект тестирования — консольная программа «Обработка матрицы с
XML-интеграцией» (вариант 4): программа меняет местами строки, содержащие
наименьший и наибольший элементы матрицы, а этапы ввода, обработки и вывода
обмениваются XML-сообщениями версии 1.0.

Цели, которые я поставил:

- проверить все модули `src/` модульными тестами;
- проверить интеграционный конвейер `input.xml → processed.xml → result.xml`;
- применить метод «чёрного ящика» варианта 4 — эквивалентное разбиение;
- дополнить его методами «белого ящика» (покрытие решений, условий и
  комбинаторное покрытие условий);
- найти, задокументировать и исправить не менее двух дефектов;
- обеспечить покрытие с ветвями не ниже 90 % (минимум по варианту — 70 %).

## 3. Стратегия

1. Эквивалентное разбиение: для каждого входа я выделил допустимые и
   недопустимые классы и взял по одному-двум представителям каждого класса.
2. Покрытие решений: каждое условие `if`/`while` в `src/` принимает значения
   «истина» и «ложь» хотя бы в одном тесте.
3. Покрытие условий и комбинаторное покрытие: для составных условий
   (`not isinstance(row, list) or len(row) != columns`,
   `processor is None` / `formatter is None`) проверены все комбинации.
4. Интеграционное тестирование конвейера: успешные сценарии и отказы
   на каждом этапе.
5. Регрессия: сначала я написал падающие тесты на дефекты, затем исправил код.

### 4.1. Классы эквивалентности

| Вход | Допустимые классы | Недопустимые классы |
|---|---|---|
| Матрица | 1×1; 1×N; N×1; N×M; числа и числовые строки; отрицательные и вещественные значения | `None`, не список, пустой список, пустая строка, строки разной длины, кортеж вместо строки, `None`/текст/вложенный список в ячейке, NaN и ±Infinity |
| Размеры при вводе | целые `rows > 0`, `columns > 0` | нечисловые, дробные, ноль, отрицательные |
| Строка при вводе | ровно `columns` чисел | меньше/больше чисел, нечисловой текст |
| Тайм-аут чтения | файл появился до истечения тайм-аута | файл отсутствует (`timeout = 0` и `timeout > 0`) |
| XML-сообщение | корень `matrix-message`, версия 1.0, заголовки совпадают с данными | битый XML, пустой файл, иной корень, иная/отсутствующая версия, нецелые или отсутствующие заголовки, несовпадение строк/столбцов, нечисловые и неконечные значения |
| Модули конвейера | заданы `processor` и `formatter` | `processor = None`, `formatter = None`, оба `None`, обработчик выбрасывает исключение или нарушает контракт |

## 5. Протокол тестирования

Команды проверки:

```powershell
python -m flake8 src tests
python -m coverage run --branch --source=src -m pytest -q
python -m coverage report --show-missing
```

| № | Сценарий | Ожидаемый результат | Фактический результат |
|---:|---|---|---|
| 1 | Корректная прямоугольная матрица 3×2 | строки 1 и 2 переставлены | пройден |
| 2 | Экстремумы в одной строке / константная матрица | матрица не меняется | пройден |
| 3 | Повторяющиеся экстремумы | используются первые вхождения | пройден |
| 4 | Пустая, рваная, нечисловая матрица | `InvalidDataError` | пройден |
| 5 | NaN/Infinity в матрице или XML | `InvalidDataError` | пройден после исправления BR-01 |
| 6 | Отсутствует XML-файл | `IntegrationTimeoutError` | пройден |
| 7 | Файл появляется с задержкой | матрица прочитана | пройден |
| 8 | Битый XML / неверный корень | `InvalidDataError` | пройден |
| 9 | Неверная версия схемы | `VersionConflictError` | пройден |
| 10 | Заголовок не совпадает с данными | `InvalidDataError` | пройден |
| 11 | Полный конвейер | три XML-файла с этапами `input`, `processing`, `output` | пройден |
| 12 | Недоступный модуль обработки или вывода | `ModuleUnavailableError` | пройден |
| 13 | Сбой нового запроса после успешного | XML-файлы прошлого запроса удалены | пройден после исправления BR-02 |
| 14 | Консольный запуск `main` | результат или «Ошибка интеграции: …» | пройден |

Итог локального прогона (Python 3.12.6, Windows):

```text

pytest                       -> 159 passed
coverage (операторы+ветви)   -> 165 операторов, 46 ветвей, 100 %
```
