## 2. Ручная инспекция исходного кода

| № | Место | Замечание | Решение |
|---:|---|---|---|
| 1 | `input_module.validate_matrix` | `float()` принимает строки `nan`, `inf`, `Infinity`; такие значения ломают поиск экстремумов (сравнения с NaN всегда ложны) | добавил проверку `math.isfinite`, дефект BR-01 |
| 2 | `integration.run_pipeline` | при сбое нового запроса в каталоге обмена остаются XML-файлы прошлого запроса, и потребитель может прочитать устаревший `result.xml` | очищаю каталог перед запуском и после любого сбоя, дефект BR-02 |
| 3 | `xml_transport.read_matrix` | ожидание файла через опрос с шагом 10 мс | допустимо для учебного транспорта; поведение покрыто тестами тайм-аута и позднего файла |
| 4 | `main.main` | перехватывается только `IntegrationError` | соответствует контракту: все ошибки модулей наследуются от `IntegrationError` |
| 5 | Общая структура | ответственность модулей разделена, валидация единая (`validate_matrix`) | замечаний нет |

## 3. Ревью тестов

| Критерий | Оценка |
|---|---|
| Независимость | каждый тест создаёт свои данные; общие константы неизменяемы по смыслу и копируются перед изменением (`[row[:] for row in ...]`) |
| Изоляция файловой системы | все тесты с XML используют встроенную фикстуру `tmp_path`; `main` с реальным конвейером запускается после `monkeypatch.chdir(tmp_path)`, поэтому каталог `integration_data/` проекта не затрагивается |
| Фикстуры | `tmp_path`, `capsys`, `monkeypatch`; собственная фикстура `console` в `TestMain` подменяет ввод размеров и матрицы |
| Подмена ввода | `monkeypatch.setattr("builtins.input", ...)` вместо реальной консоли |
| Параметризация | `pytest.mark.parametrize` задаёт по одному представителю на класс эквивалентности |
| Читаемость | тесты сгруппированы по модулям в классы, имена описывают проверяемый класс или решение |
| Многопоточность | тест позднего файла пишет во временный файл и атомарно переименовывает его, поток завершается через `join()` |
| Регрессия | тесты BR-01 и BR-02 сохранены в `TestRegression` и запускаются в CI |
| Порядок запуска | тесты не зависят от порядка выполнения |
